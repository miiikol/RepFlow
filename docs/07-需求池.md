## 1. 优先级方法

采用“价值 × 复杂度”二维评估，再映射到 MoSCoW：

| 象限         | 判断      | 处理           |
| ---------- | ------- | ------------ |
| 高价值 + 低复杂度 | 快速拿下    | P0 / Must    |
| 高价值 + 高复杂度 | 拆小或放标准版 | P1 / Should  |
| 低价值 + 低复杂度 | 顺手做     | P2 / Could   |
| 低价值 + 高复杂度 | 不做      | Out of Scope |

优先级口径：

- **P0**：主流程闭环必需，缺失则无法演示；
- **P1**：显著提升可信度或降低风险，时间允许就做；
- **P2**：锦上添花，不影响主流程；
- **Out**：与项目规模或目标岗位不匹配。

## 5. 维护规则

1. 新需求先入池，不直接进迭代；
2. P0 需求必须能映射到验收标准与测试用例；
3. 不做需求必须写理由与重新评估条件，避免“拍脑袋砍需求”；
4. 每次版本发布后更新状态，保持与 `08-需求追溯矩阵.md` 一致。
