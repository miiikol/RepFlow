## 1. 测试目标

1. 验证需求主流程的关键约束：合法/非法状态流转、角色越权、归档只读；
2. 验证数据权限在列表、详情、跨表查询上的一致性；
3. 验证并发场景：乐观锁冲突、业务编号并发唯一；
4. 验证接口层安全：未登录 401、无权限 403、数据越权 403、账号锁定；
5. 为面试提供可复现的质量证据，而不是只写“测试通过”。

## 5. 缺陷与风险

### 5.1 已修复问题（本轮工程加固）

| 问题                            | 修复方式                                   |
| ----------------------------- | -------------------------------------- |
| 数据权限“列表 SQL + 详情 Java”两套实现易漂移 | 收敛为 `DataScopeService` 单一谓词            |
| 并发流转可能后提交覆盖先提交                | 需求表增加 `lock_version`，统一 `persist()` 入口 |
| 编号生成依赖 `synchronized`，多实例不安全  | 改为序号行原子自增 + 独立事务                       |
| 看板把全量数据拉进内存聚合                 | 改为数据库 `GROUP BY`                       |
| 详情页重复全表扫描                     | 改为按需求 ID 精确查询                          |

### 5.2 已知风险

| 风险                    | 影响           | 建议                        |
| --------------------- | ------------ | ------------------------- |
| 未做性能压测                | 无法量化 P95/QPS | 投递前用 JMeter 压登录、列表、看板，补数据 |
| 无前端自动化测试              | 前端回归靠手工      | 至少补登录与需求列表的 Vitest 用例     |
| 测试断言依赖 seed 固定 ID/总数  | 改演示数据会红      | 改为 fixture 构造数据           |
| 审计写入使用 `REQUIRES_NEW` | 高并发下占用额外连接   | 压测观察连接池，必要时改异步            |
| 覆盖率为 0 度量             | 无法证明覆盖广度     | 引入 JaCoCo，先设 50% 门槛       |

## 6. 测试结论

- 自动化测试 33/33 通过，核心高风险路径（越权、非法流转、并发冲突、编号并发）均有覆盖；
- 手工清单尚未全部复测，投递前需按第 4 节完成并回填《09-验收记录.md》；
- 项目达到“可演示、可讲清”的质量门槛，但不满足“有性能数据”的加分项；
- 建议投递前优先补：性能压测、前端冒烟测试、手工清单复测截图。
