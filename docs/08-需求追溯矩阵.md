## 3. 覆盖检查

### 3.1 已覆盖

- 7 个 P0 主流程需求（RQ-001/008/011/016/019/026/027）均有接口、代码与测试/验收证据；
- 4 档数据权限在列表、详情、跨表查询三个入口均复用同一谓词；
- 状态机的 13 条自动化用例覆盖合法流转、非法流转、角色越权、挂起恢复、提测前置。

### 3.2 未闭环项

| 需求             | 缺口             | 影响          | 补齐动作              |
| -------------- | -------------- | ----------- | ----------------- |
| RQ-018 会签强校验   | 只记录意见，不校验全部通过  | 评审严谨性不足     | 标准版增加“全部意见通过”规则   |
| RQ-021 两级审批    | 单级审批           | 审批场景不完整     | 按工时阈值增加二级审批       |
| RQ-025 工时明细    | 仅任务级实际工时       | 无法按人/天汇总    | 增加 worklog 表与汇总接口 |
| RQ-033 Word 导出 | 未实现            | 文档生成能力缺失    | 接入 poi-tl         |
| RQ-034 通知      | 未实现            | 提醒依赖人工查看待办  | 增加通知表与定时任务        |
| RQ-035 部门/字典管理 | 未实现页面          | 配置依赖初始化 SQL | 增加管理页面            |
| RQ-042 性能压测    | 无数据            | 无法量化性能      | JMeter + 慢 SQL 分析 |
| RQ-043/044/045 | 前端测试、测试去脆化、覆盖率 | 质量证据不足      | 上线前优先补 042 与 043  |

### 3.3 孤儿需求检查

- 需求池 45 条需求均有状态与去向，无“无来源、无去向”的孤儿需求；
- 代码侧未发现无法回溯到需求池的核心 Service（工具类与基础设施除外）。

## 4. 维护约定

1. 新增需求必须先分配 RQ 编号，再改本文与需求池；
2. 新增接口必须补一行追溯，写明 Controller/Service 与测试；
3. 测试用例命名尽量体现业务语义，便于反查；
4. 每次发布前检查“未闭环项”，不允许 P0 需求停留在未实现。
