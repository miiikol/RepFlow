# ReqFlow 部署与运行手册

| 项目   | 内容                                   |
| ---- | ------------------------------------ |
| 文档编号 | REQFLOW-OPS-001                      |
| 版本   | V1.0                                 |
| 编写日期 | 2025-11-11                           |
| 适用版本 | `1.0.0`                              |
| 部署形态 | 单体应用 + 前端静态资源 + MySQL（可选）+ Nginx（可选） |

---

## 1. 部署架构

```
浏览器
  │
  ├── 开发模式：Vite 5173 ──/api 代理──▶ Spring Boot 8080
  │
  └── 生产/演示：Nginx 80 ──反向代理──▶ Spring Boot 8080 ──▶ MySQL 3306
```

| 组件      | 端口   | 说明                         |
| ------- | ---- | -------------------------- |
| 前端开发服务器 | 5173 | Vite，仅开发时使用                |
| 后端应用    | 8080 | Spring Boot，同时托管构建后的前端静态资源 |
| MySQL   | 3306 | 可选，默认使用 H2 文件库             |
| Nginx   | 80   | Docker Compose 场景下的统一入口    |

## 3. 方式一：本地 H2 一键启动（推荐演示）

### 3.1 构建前端（首次必做）

前端构建产物**不入库**，需要本地生成：

```bash
cd frontend
npm install
npm run build
```

Vite 输出目录为 `backend/src/main/resources/static`。

### 3.2 启动后端

```bash
cd backend
mvn spring-boot:run
```

首次启动由 Flyway 自动建表并写入演示数据，数据库文件位于 `backend/data/reqflow.mv.db`。

### 3.3 访问

| 入口     | 地址                                      |
| ------ | --------------------------------------- |
| 系统首页   | <http://localhost:8080/>                |
| 接口文档   | <http://localhost:8080/swagger-ui.html> |
| H2 控制台 | <http://localhost:8080/h2-console>      |

H2 连接信息：JDBC URL `jdbc:h2:file:./data/reqflow`，用户 `sa`，密码为空。

---

## 4. 方式二：前后端分离开发

```bash
# 终端 1
cd backend
mvn spring-boot:run

# 终端 2
cd frontend
npm install
npm run dev
```

访问 <http://localhost:5173>。Vite 已配置 `/api` 代理到 `http://localhost:8080`。

---

## 5. 方式三：MySQL 8

### 5.1 建库

```sql
CREATE DATABASE reqflow DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### 5.2 启动

```bash
cd backend
set DB_PASSWORD=你的密码
mvn spring-boot:run -Dspring-boot.run.profiles=mysql
```

PowerShell 使用 `$env:DB_PASSWORD="你的密码"`。

可用环境变量：

| 变量                | 默认值              | 说明                |
| ----------------- | ---------------- | ----------------- |
| `DB_HOST`         | `localhost`      | 数据库地址             |
| `DB_PORT`         | `3306`           | 端口                |
| `DB_NAME`         | `reqflow`        | 库名                |
| `DB_USER`         | `root`           | 用户名               |
| `DB_PASSWORD`     | `root`           | 密码                |
| `JWT_SECRET`      | 内置演示值            | 生产必须替换，长度 ≥ 32 字节 |
| `REQFLOW_STORAGE` | `./data/uploads` | 附件目录              |

Flyway 会自动执行 `classpath:db/migration` 下的同一套脚本。

## 6. 方式四：打包为可执行 jar

```bash
cd backend
mvn clean package -DskipTests
java -jar target/reqflow-backend-1.0.0.jar
```

- 前端需先构建到 `static`，否则首页 404；
- 可用 `java -jar app.jar --spring.profiles.active=mysql` 切换数据库；
- 生产建议用 `nohup` 或 systemd 托管，并配置日志轮转。

---

## 7. 方式五：Docker Compose

### 7.1 准备配置

```bash
copy .env.example .env
```

`.env` 至少修改：

```ini
MYSQL_ROOT_PASSWORD=强密码
JWT_SECRET=至少32字节的随机字符串
```

### 7.2 启动

```bash
docker compose up -d --build
```

### 7.3 访问

<http://localhost>（Nginx 80 → app 8080）。

### 7.4 常用命令

```bash
docker compose ps
docker compose logs -f app
docker compose down
docker compose down -v   # 同时删除数据库与附件卷，慎用
```

Compose 已配置 MySQL healthcheck，应用在数据库健康后启动；MySQL 数据与附件分别使用命名卷持久化。

## 8. 初始化、重置与备份

### 8.1 重置演示数据（H2）

```bash
# 1. 停止应用
# 2. 删除 data 目录
Remove-Item -Recurse -Force backend\data
# 3. 重新启动，Flyway 自动重建
```

### 8.2 备份

| 对象    | 方式                                                   |
| ----- | ---------------------------------------------------- |
| H2    | 复制 `backend/data/reqflow.mv.db`                      |
| MySQL | `mysqldump -uroot -p reqflow > reqflow_20261111.sql` |
| 附件    | 打包 `REQFLOW_STORAGE` 目录                              |

### 8.3 恢复

1. 停止应用；
2. 恢复数据库文件或执行 SQL 导入；
3. 恢复附件目录；
4. 启动应用，验证登录、需求详情、附件下载。

---

## 9. 升级与回滚

1. 备份数据库与附件；
2. 拉取新版本代码，执行 `mvn clean package`；
3. Flyway 自动执行新增迁移脚本（只允许新增 `V4__xxx.sql`，禁止改历史脚本）；
4. 验证首页、登录、需求列表、详情；
5. 回滚：切回上一版本 jar + 恢复备份数据库。

## 11. 常见问题

| 现象                             | 原因              | 处理                                 |
| ------------------------------ | --------------- | ---------------------------------- |
| 首页 404                         | 前端未构建           | `cd frontend && npm run build`     |
| `Port 8080 was already in use` | 端口占用            | 停止占用进程或 `--server.port=8081`       |
| esbuild 构建报临时目录权限错误            | Windows TEMP 权限 | 将 `TEMP/TMP` 指向项目内可写目录             |
| 登录 401                         | Token 缺失或过期     | 重新登录，检查 `Authorization` 头          |
| Flyway 校验失败                    | 修改了已执行的迁移脚本     | 恢复脚本；新增变更用新版本号                     |
| H2 控制台打不开                      | 生产 profile 未开启  | 仅演示 profile 开放，生产不建议开启             |
| Docker 应用启动失败                  | MySQL 未健康       | `docker compose logs mysql`，确认密码一致 |
| 附件下载 404                       | 存储目录迁移或卷丢失      | 恢复 `REQFLOW_STORAGE` 目录            |

## 12. 安全加固建议

1. 生产必须替换 `JWT_SECRET` 与数据库密码，禁止使用仓库默认值；
2. 关闭 H2 控制台，使用 MySQL；
3. Nginx 配置 HTTPS，限制请求体大小与超时；
4. 数据库账号按最小权限分配，应用账号不授予建库/删表权限；
5. 附件目录禁止执行权限，定期备份；
6. 审计日志只读，保留周期按合规要求设置；
7. 公网部署时，Swagger 建议加鉴权或仅内网开放。
