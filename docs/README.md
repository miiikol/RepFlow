## 2. 推荐阅读顺序

**面试官/评审人（10 分钟）**

1. 根目录 `README.md`：项目定位、架构、启动方式；
2. `01-需求规格说明书.md`：范围、角色、状态机；
3. `04-测试报告.md`：质量证据；
4. `09-验收记录.md`：交付结论。

**需求/产品岗面试（15 分钟）**

1. `06-需求调研纪要.md`：怎么问、怎么归纳；
2. `07-需求池.md`：怎么排优先级、怎么砍范围；
3. `08-需求追溯矩阵.md`：需求如何落到实现；
4. `01-需求规格说明书.md`：最终规格。

**开发/测试岗面试（20 分钟）**

1. `02-接口文档.md` + `api/openapi.json`；
2. `03-数据库设计说明.md`；
3. `04-测试报告.md`；
4. `05-部署手册.md`。

## 3. 材料性质说明

| 文档 | 性质 |
|---|---|
| 01/02/03/05 | 基于实际代码与配置整理，可作为技术事实 |
| 04 | 自动化结果来自 surefire 报告；手工清单明确标注“待复测” |
| 06 | **角色化模拟调研**，不是真实企业访谈 |
| 07/08 | 基于模拟调研与实现反推的需求管理材料 |
| 09 | **开发自验**，签字为作者本人，不是第三方验收 |

面试表达时请保持同样口径，不要把模拟材料说成真实客户交付。

## 4. 维护方式

1. **接口变更**：修改 Controller 后重新导出契约：

   ```bash
   curl -s http://localhost:8080/v3/api-docs -o docs/api/openapi.json
   ```

2. **数据库变更**：只新增 `V4__xxx.sql`，同步更新 `03-数据库设计说明.md`；
3. **需求变更**：先改 `07-需求池.md` 状态，再更新 `08-需求追溯矩阵.md` 与 `01-需求规格说明书.md`；
4. **测试变更**：执行 `mvn test` 后更新 `04-测试报告.md` 的用例数与结果；
5. **验收前**：按 `09-验收记录.md` 第 9 节逐项复测并回填日期。
